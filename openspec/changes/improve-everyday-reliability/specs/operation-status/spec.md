# Spec Delta

## Purpose

Объясняет пользователю текущую доступность автоматического и ручного исправления одинаково во всех точках интерфейса приложения.

## ADDED Requirements

### Requirement: Актуальная причина состояния
Система SHALL различать выключение пользователем, отсутствие разрешений, защищённый ввод, приостановленную сессию, недоступный обработчик, ручной режим и разрешённое автоисправление.

#### Scenario: Приоритет блокирующей причины
- **WHEN** одновременно присутствуют несколько ограничений
- **THEN** основная причина выбирается в порядке: выключение, приостановленная сессия, разрешения, защищённый ввод, обработчик, ограничения приложения или поля, ручной режим, автоматический режим

#### Scenario: Исключённое приложение
- **WHEN** обработчик доступен, но текущее приложение исключено
- **THEN** статус сообщает об отключении автоисправления в этом приложении и не обещает доступность ручной замены в непроверенном поле

#### Scenario: Неподдерживаемое поле
- **WHEN** нельзя подтвердить доступность поля для исправления
- **THEN** интерфейс сообщает об ограничении или неизвестной доступности, не заявляя готовность конкретного поля

### Requirement: Согласованность интерфейса
Система SHALL отображать одно текущее состояние в меню, подсказке значка и настройках, отдельно от последнего диагностического события.

#### Scenario: Смена состояния
- **WHEN** меняются настройки, приложение, разрешения, Secure Input либо состояние обработчика
- **THEN** все точки интерфейса обновляются не позднее следующего цикла проверки состояния и при открытии меню
- **THEN** старое сообщение об успешном исправлении не подменяет текущую причину недоступности

### Requirement: Статус без содержимого ввода
Система SHALL формировать статусы без сохранения или показа содержимого поля и введённых слов.

#### Scenario: Диагностика ограничения
- **WHEN** исправление недоступно
- **THEN** статус содержит причину, при необходимости название приложения, но не текст пользователя
