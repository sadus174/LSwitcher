# Локальная сборка и доверенный выпуск

Требуются Swift 6/Command Line Tools и Python 3. Node.js/OpenSpec используются для планирования и не входят в приложение.

## Локальная сборка

```sh
bash scripts/build-dmg.sh
```

Создаёт ad-hoc приложение и DMG в `dist/`; это не нотариализованный выпуск. Скрипт проверяет подпись, целостность DMG и прежний лимит размера 2 687 792 байта. Иконки и готовый словарь берутся из репозитория. Необязательная регенерация иконок требует локальных инструментов, не входящих в минимальный процесс выпуска.

## Описание релиза

Публичное описание содержит изменения приложения и сведения для установки. Результаты внутренних прогонов, отчёты о разработке и инструменты подготовки не включаются в описания релизов. История пользовательских изменений ведётся в CHANGELOG.md.

## Статус релиза

Отсутствие Developer ID или нотариализации Apple само по себе не делает версию Preview. Проверенные ad-hoc сборки можно публиковать как обычные релизы и предлагать через встроенное обновление. Пометка Preview используется для предварительных изменений с отдельными функциональными причинами. В описании каждого релиза сохраняйте точные сведения о подписи, нотариализации и возможной повторной выдаче разрешений. Платная подписка Apple Developer Program не является условием публикации релиза этого проекта.

## Необязательные Developer ID и нотариализация Apple

Нужны действующая Developer ID Application identity в локальной связке ключей и заранее настроенный профиль `notarytool`. Не помещайте пароли, сертификаты и закрытые ключи в репозиторий или чат.

```sh
SIGN_IDENTITY='Developer ID Application: YOUR NAME (TEAMID)' \
NOTARY_PROFILE='your-existing-keychain-profile' \
REQUIRE_NOTARIZATION=1 bash scripts/build-dmg.sh --preflight-only
```

Для сборки повторите команду без `--preflight-only`. Проверка профиля обращается к Apple. Подписание выполняется изнутри наружу: updater, затем приложение, с hardened runtime и timestamp. Сначала нотариализуется архив приложения и билет прикрепляется к `.app`; затем создаётся и отдельно нотариализуется DMG. Непринятая отправка останавливает процесс, а итог проверяется stapler/codesign/Gatekeeper.

Результаты принятых отправок и журналы Apple сохраняются в `dist/notarization/<version>/`. Просмотрите журналы на предупреждения даже после успешного принятия; при отклонении сохранён результат отправки. Эти файлы не входят в DMG или ZIP обновления.

Порядок соответствует [документации Apple](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow): ZIP не поддерживает прикрепление билета, поэтому билет прикрепляется к приложению до изготовления финального ZIP.

## Встроенное обновление

Добавьте `WITH_UPDATE=1` и при необходимости `UPDATE_SIGNING_KEY=/absolute/path/to/key` к команде сборки. По умолчанию ключ берётся из игнорируемого `keys/update-signing.key`. Скрипт не выводит ключ и проверяет соответствие закреплённому публичному ключу приложения. Финальный ZIP создаётся после stapling; только затем вычисляются размер, SHA256 и подписывается `update.json`.

Схема обновлений пока описывает одну архитектуру; для `WITH_UPDATE=1` собирайте отдельные arm64/x86_64 пакеты на соответствующем хосте. `UNIVERSAL=1` доступен для отдельного DMG без манифеста обновления.

## Проверки

```sh
swift run -c release LSwitcherChecks
python3 scripts/test-release-workflow.py
# После сборки с WITH_UPDATE=1:
python3 scripts/test-updater.py
```

Первая проверка — ядро; вторая использует временные проекты и имитацию Apple, без сетевых отправок и доступа к ключам; третья проверяет настоящий updater на временной копии приложения и подписанном пакете. Ни одна из этих проверок не подтверждает сама по себе реальную нотариализацию.

На реальных артефактах дополнительно проверьте первый запуск и приложение из ZIP, а также переход с ad-hoc версии. Отдельно зафиксируйте, потребовала ли macOS повторно выдать Accessibility/Input Monitoring. Скрипты ничего не публикуют на GitHub и не меняют `/Applications`.
